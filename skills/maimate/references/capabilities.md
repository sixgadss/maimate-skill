# 能力与数据接入

## 三种环境

| 环境 | 可执行范围 |
| --- | --- |
| 已连接的 mcmate Runtime | 按实际 schema 执行推荐与偏好管理；默认 stdio 只读 |
| 已连接的官方麦当劳 MCP / App 业务工具 | 按已发现 schema 补足菜单、精确核价等操作；每项能力单独验证 |
| 没有相关工具 | 只能整理当前需求与展示明确标注的产品概念；不报实时价，不宣称持久记忆 |

本包 `runtime/` 可选后端位于仓库根目录。安装 Skill 不等于启动后端，也不等于自动接入官方账号。读取 Runtime 工具时使用同目录 runtime-contract.md，参数不明不要猜。

## 发现与校验

读取实际工具列表与输入输出 schema，记录菜单、门店、渠道、商品规格、营养、持有优惠、完整报价、历史订单、记忆写入、收藏、订单提交和订单查询各自是否可用。没有对应工具即不可用。工具改版或账号、门店切换后重新检查相关范围。

官方平台及文档入口：

- https://open.mcd.cn/mcp
- https://open.mcd.cn/mcp/doc

公开平台描述不能证明当前账号已授权或调用成功。文档可能更新，原生工具名和参数以实际发现为准。不要把社区整理的参数当成已验证结果。

对每次成功数据核对：用户与门店、业务实体、渠道、履约时间、商品 ID 与规格、数量、券资格、完整费用、币种及时间有效性。原生金额单位须有 schema 或映射证据；不知道元还是分时不能猜。规范金额使用整数分。

只有同时满足以下条件，才能把报价作为可选结果：

1. 业务明确成功，商品和范围与请求一致，没有未知替换。
2. 商品可售，必选规格齐全。
3. 必付费用完整、实付总额已核验、报价尚有效。
4. 硬预算、饮食限制与人数分配满足；未知营养或配料不能当作符合限制。

折扣只用完整报价中的结果；不自行叠券、重复减券或根据营销小字推算优惠。查询失败应保留错误状态，不能转成“没有优惠”。

## Runtime 与原生查询的衔接

能力按操作择路，不要求单一服务包办所有任务。比如 Runtime 没有精确篮子参数，但真实原生工具可以核价指定商品时，直接走该能力；不得把单品意图改成推荐意图。

原生结果须满足上面的四项事实核验。经过授权工具直接返回的权威完整报价可以作为核验来源，不因缺少某个特定 Runtime 组件而强行降级。金额格式与可重复的计算应使用确定性处理；缺单位、费用、范围、有效期或限制证据时保持草稿，并说明缺失项。不要把未经验证的原生载荷冒充 Runtime 已验收的结果。

重试只适用于明确可重试的读取操作，失败一次后按服务给出的限制或退避要求处理。保持一个具体下一步，不无限重试。提交订单或消耗权益超时先查状态，不能视为失败后重做。

## 无权限时

不要求用户把 Token、密码、验证码贴入聊天。凭据通过宿主配置或官方登录通道提供，不输出到结果、记忆或文档。普通 `userTurnRef` 字符串不能证明用户授权；来源验证是宿主职责。

如真实功能受阻，继续完成当前会话能做的部分。对未完成的保存、核价或下单直接说明状态，不把“已选定”写成“已下单”。

## 本仓库新增的本机体验

仓库 runtime 的 `npm run web` 提供单人、立即到店自取的预算配餐网页；默认合成数据，用临时 SQLite，不保存长期偏好。网页不是官方 App 集成。Skill 安装只复制本包文件，不会启动网页。

`npm run official:inspect` 仅发现五个只读工具及 schemaHash。发现成功不等于账号验收。官方 pickup 工厂提供经过合成契约测试的映射，默认 document_tested；只有本机实际账号复核后才可声明 account_verified。工具缺失或 schema 改变时整条链停用，不退回示例。营养缺糖、未知商品/规格、未经核实套餐或券不兼容时保持未知/不可用。
