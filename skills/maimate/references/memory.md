# 个人记忆与麦之宝库

## 分清四类信息

| 信息 | 可做什么 | 不代表什么 |
| --- | --- | --- |
| 明确偏好 | 有来源的长期限制或喜欢 | 同伴喜好、当前一次拒绝 |
| 完成订单 | 形成上次那份与可解释的行为推断 | 喜欢所有单品、确定吃过每件商品 |
| 收藏组合 | 用户主动保存的命名配方 | 锁价、永久可售、本人永久口味 |
| 持有优惠 | 当前账户中经核验的权益 | 所有营销活动都已领取 |

想尝试是意愿，不算吃过。没有收藏接口时不能把 `mcmate_memory list` 当收藏列表，也不能把 accepted feedback 当保存组合。

## 写入条件

先区分“今天不要”与“以后不要”。当前请求保留在会话；明确长期声明通过实际记忆能力写入。Runtime 默认只读模式没有可信用户来源，不执行持久变更。不能自己编引用、通过模型提供一个非空 turnId，或调用 CLI 代替真实宿主来源验证。

保存成功需持久化工具明确返回成功及对象标识；否则如实说明只在本轮保留。无持久能力不自行把用户信息写入工作区文件作为替代。用户明确要求导出餐单文件时可按请求范围导出，但不能将文件称为已接通的 App 收藏。

多人订单不自动学习为本人偏好。“以后照这个来”可保存经过用户确认的整个组合（若有收藏工具）；同伴的偏好仍不成为本人画像或同伴永久档案。没有收藏能力则解释未保存，保留本次配方。

普通口味的当前明确例外不修改长期记忆。过敏等安全限制不能因为点选商品而自动解除；缺配料与过敏原证据时不宣称适合。

## 管理操作

查看时说明是用户明确声明还是行为推断，保留来源、范围和过期语义。推断用“最近比较常选”，不冒充用户原话。

更正、忘记、暂停、恢复和清空按工具实际支持范围执行。短期 Undo 仅使用工具返回引用；不在聊天中复制被彻底删除的数据以备恢复。删除后的旧历史不应重新学习该项，Runtime 按其已有重放阻止机制处理。

暂停学习不一定删除已有偏好；清空本地偏好不等于删除供应商远程订单。交易缓存若不在工具删除范围，明确说明。

接受推荐不构成完成订单。餐后反馈需来自用户或已验证来源，不自动制造“满意”。不收集与点餐无关的人物、情绪和人生事件；用户另有明确请求时另行处理其范围。

## 宝库浏览

有真实收藏能力才列“常点组合”；有持有优惠查询才列“我的优惠”；有愿望清单能力才持久展示“想尝试”。缺失的分区不造空数据来伪装正常读取，也不将推荐历史偷换成收藏。

商品下架或券失效时展示状态，提供重新核验或替换入口。每次从收藏进入点餐都创建新草稿并重新核价。
