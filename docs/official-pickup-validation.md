# 官方到店自取：本机接入与验证

截至 2026-10-11，本仓库为 **document_tested**：公开文档已研究，合成契约测试已运行。实际账号为 **未验收**；诊断返回 `AUTH_REQUIRED`，没有发起业务查询。测试里模拟的 account_verified 不代表维护者或使用者账号已通过。

资料：[官方接入文档](https://open.mcd.cn/mcp/doc)，本次读取版本日志最新为 1.0.9（2026-09-10）。公开文档不能替代实际 tools/list 和账号响应。

## 配置顺序

1. 在官方平台申请个人凭据，通过本机终端或宿主环境注入 `MCD_MCP_TOKEN`。不要在聊天、代码、截图或公开 Issue 中填写 Token。本程序不会自动加载 `.env`。
2. 在 runtime 执行 `npm run official:inspect`。只发现工具，不查询账户业务。输出只含五个读取工具名、输入/输出 schema 的 SHA-256 和安全错误码；`discovered` 仅表示发现成功。
3. 通过本机 MCP 客户端按实际 schema 查询附近门店，由用户选定门店及业务实体，再设置 `MCMATE_RESTAURANT_ID`、`MCMATE_BUSINESS_ENTITY_ID`。不要把文档示例编码当实际门店。
4. 用实际账号只读核对菜单、必要详情、当前门店券与算价。确认下面的检查表，再创建本机私有 JS 模块，默认导出 `createOfficialPickupProfile(review)` 的结果。工厂位于构建后的 `runtime/dist/providers/official-pickup-profile.js`，复核结构见对应 TypeScript 文件。配置 `MCMATE_BINDING_MODULE` 为此模块的绝对路径。它是本机可执行代码，只加载自己审核过的模块。
5. 设置 `MCMATE_PROVIDER=live` 后 `npm run web`。网页始终单人、立即到店自取、临时记忆。没有经过账号复核的 profile，或工具 schema 改变/缺失时显示不可用；不会回退示例。

`PickupReview` 需明确总体 status、每个操作的 status/schemaHash、选定门店、金额单位、完整费用字段、当前列表可售语义和精确商品证据。保留 document_tested 时全部真实绑定关闭。只有实际复核过的操作才写 account_verified；五项操作缺一项，链路都不启用。这个标志是本机人工复核声明，不是工厂自动完成的认证。

推荐只纳入审核过的单品默认组成，精确匹配商品编码和名称。未知分类、鸡肉标签、糖证据保持未知，名称与促销标签不等于食材/营养证据。套餐与特调尚未支持，不填写假默认组成。营养公开例子没有糖字段，不能当作零糖。

菜单/详情按元转换；算价按分处理。字段单位必须再经账号核对。报价校验商品/数量、分项小计、原价、必付配送/餐具费、折扣和实付之间的等式。缺费用字段不声明完整报价；未知额外字段拒绝。随单购会员价格排除，不自动购买会员。菜单 withOrder 只接受缺省或 null；报价 takeWayList / mealAssistanceList 只接受缺省或空数组。任何其他附加元数据尚未复核其资格、组成与费用语义，因此拒绝，不能用促销名称推断安全。这会缩小当前可用覆盖，需真实只读复核后才能扩展。券仅用当前门店查询的 ID/code、有效期和适用商品；仅唯一匹配的一件商品可带券，不叠券。

`serviceAt` 只用于本餐上下文；即时映射省略 reservationDate，拒绝未来预约、外送和积分计划。报价刷新窗口为本机 30 秒，不是上游锁价。

## 真实复核检查表

| 项目 | 本次状态 | 实际账号需核对 |
| --- | --- | --- |
| tools/list | AUTH_REQUIRED | 五个工具均存在，实际 schemaHash |
| 用户选店与渠道 | 未调用 | 门店/BE、到店自取的业务编码 |
| 菜单金额与可售语义 | 契约测试 | currentPrice 单位、随单购、实际可售 |
| 单品默认组成、分类、食材 | 契约测试 | 精确 ID/名称、默认规格、证据来源 |
| 糖限制 | 缺糖保持未知测试 | 能证明的饮品规格；缺证据应拒绝 |
| 券 | 契约测试 | 持有/有效期/适用商品/唯一绑定 |
| 算价 | 契约测试 | 分值、商品数量、全部费用、优惠资格 |
| 报价与网页 | 合成映射联调 | 实际门店完整价格；断开不降级示例 |

不要保存原始账号载荷到仓库。仅在本机私有复核记录里写日期、通过项目与剩余问题。账号、门店、接口或商品默认组成变化后重新复核。
